# Web 画面の設計

## 目的

- ハッカソンのデモと、友人との実地実験の両方に使える Web 画面を作る
- OSS として公開できる品質にする
- スマホ向けを最優先にする（GPS を取るのはスマホのため）
- REST API（`docs/architecture.md`）の1クライアントとして作り、将来のネイティブアプリでも同じ API を使う

## 決めたこと（要約）

| 項目 | 決定 |
|---|---|
| 画面の形 | Google マップのような全画面の地図。ピンに「水」「食」などの文字。ピンの詳細は地図を暗くしない下のシート、右下に現在地ボタン |
| ピン | 白い縁の丸に一文字、下に名前。紺＝非公式・確認済み / オレンジ＝未確認（全員に表示） / 緑＝公式の避難所 |
| 近くの人への質問 | 画面を開いている間だけ、画面内のカードで通知 |
| 自分から知らせる | 下の6つのボタン → 備考（任意）→ 送信。まず未確認として載る |
| 確認済みになる条件 | 検知の候補は1人の回答、報告の候補は報告者を含めて2人 |
| ピンが消える条件 | 最後の確認から3時間で薄く、6時間で消える ＋「もう終わっていた」の多数決 |
| 備考 | 100文字まで、URL・電話番号は不可、通報2件で非表示、ピンと一緒に消える |
| 公式拠点 | BODIK 令和8年熊本地震 避難所データ（開設・閉鎖の日時つき） |
| 施設 | 八代市の店・病院・役所・学校・公園などを、拡大すると Google マップのような種類の印と名前で出す（§1.7） |
| 技術 | HTML/JS を直接書く（ビルドなし）＋ MapLibre GL ＋ OpenFreeMap |
| 見た目 | 白基調に紺のアクセント。地図は Apple マップのような柔らかい配色。端末のダークモード設定に自動で合わせる |
| PWA | ホーム画面に追加できるところまで（Service Worker なし） |

## 1. 画面と操作

### 1.1 初回起動（説明と同意）

- 次のことを説明し、「同意して始める」ボタンを置く
  - 送るのは位置だけで、名前や連絡先は送らない（匿名）
  - 少人数の集まりは地図に表示しない
  - メニューからいつでも参加をやめ、送ったデータを消せる
- 同意したら `POST /v1/sessions` でトークンを受け取り、`localStorage` に保存する
- 続けて位置の利用許可を求める。許可しなくても地図は見られる

### 1.2 地図（メイン画面）

- 全画面の地図に、次の3種類のピンを立てる

| ピン | 色 | 文字 | 意味 |
|---|---|---|---|
| 非公式・確認済み | 紺の塗り | 水 / 食 / 物 / 宿 / 避 / 他 | 回答が多い種類の頭文字（同数なら先に回答が付いた種類） |
| 未確認 | オレンジの塗り | `?` または `水?` など | 検知だけなら `?`、報告があればその種類＋`?` |
| 公式の避難所 | 緑の塗り（避難場所の標識の色） | 避 | BODIK のデータ |

- ピンは白い縁の丸（中心が地点）。丸の下に名前を出す: 公式は施設名、それ以外は種類（給水など。種類がまだなければ「人の集まり」）。デモの候補の正解の名前は出さない
- 名前がほかのピンの丸や先に出した名前と重なったら隠す。種類の名前を施設名より先に出す。公式のピンは下に描き、同じ場所の検知・報告のピンを隠さない
- 最後の確認から3時間たったピンは薄く表示する（6時間でサーバーが返さなくなる）
- 上部: 絞り込みのチップ（すべて / 給水 / 食べ物 / 避難。種類の札つき、横に流せる）とメニューボタン
- ピンをタップすると、下にシートを出す（Google マップ・Apple マップで場所を押したときと同じ形）
  - 地図は暗くせず、触れるまま（モーダルにしない）。ほかのピンを押すと中身が入れ替わる
  - 押したピンは 1.3 倍に大きくして前に出す
  - 種類の札と見出し、現在地からの距離（「ここから 350m」）、種類ごとの回答数、最後の確認時刻、備考の一覧
  - 「まだやっている」「もう終わっていた」ボタン（非公式のピンのみ）
  - 備考ごとの「不適切」通報ボタン
  - 閉じ方: ✕、つまみを下に引く、地図（ピン以外）を押す、Esc
- 現在地を青い点で表示する。右下の丸いボタンで現在地に戻る

### 1.3 近くでの通知（「ここに何がある？」）

- 画面を開いている間、位置を記録し、約1分ごとにまとめて `POST /v1/locations` で送る
- 送るたびに `GET /v1/questions` を呼び、未回答の未確認ピンが 500m 以内にあれば、画面上部にカードを出す
- カードの選択肢: 給水 / 食べ物 / 物資 / 宿泊・車中泊 / 避難 / わからない
- 画面を閉じている間の通知はしない（Web では位置が取れないため。ネイティブ化のときに対応する）

### 1.4 自分から知らせる

- 画面下部のドックに6つのボタン: 給水 / 食べ物 / 物資 / 宿泊・車中泊 / 避難 / その他
- ボタンを押すとシートが開き、種類の選択・備考の入力欄（任意、100文字まで）・送信ボタンを出す
- 送信すると `POST /v1/reports` に今いる位置を付けて送り、オレンジのピンが立つ

### 1.5 メニュー

- このアプリについて
- データの扱い（何を送り、どう使い、いつ消えるか）
- 参加をやめてデータを消す（確認のうえ `DELETE /v1/sessions/me` → 同意の画面に戻る）
- 出典の表示（OpenFreeMap / OpenMapTiles / OpenStreetMap / BODIK）
- GitHub へのリンク

### 1.6 見た目

- 白を基調に紺（`#1e3a5f`）をアクセントにする。未確認はオレンジ（`#ea8a00`）、公式の避難所は緑（`#0f7b4f`）。面と文字は少し青みのある無彩色にし、色が付くのはピンと札だけにする
- 種類は絵文字ではなく、ピンと同じ「漢字1文字の札」（水・食・物・宿・避・他、わからないは「？」）で示す。知らせるボタン・質問の選択肢・質問カードの見出しで共通に使う
- メニューと閉じるは線のアイコン（lucide と同じ形、18px・線の太さ 1.5）。文字の太さは 400 と 600 だけ、余白は 4px 刻み
- 色は CSS 変数にまとめ、`prefers-color-scheme: dark` で暗い配色に切り替える
- 背景の地図は、明るいときは OpenFreeMap の `liberty`（公園・建物まで載っている。施設は §1.7）、暗いときは `dark` に切り替える
- 地図は Apple マップのような柔らかい配色に塗り直す（`MAP_PAINT`）: 温かい地面、緑の公園、青い水、白い道、幹線は淡い黄色。暗いときは真っ黒にせず、灰色の地面に紺の水と深い緑の公園
- 立体の建物は出さない（古いスマホで重い）。平らな建物も、拡大したとき（ズーム 15 以上）だけ出す
- 地図の出典は左下の「ⓘ」に畳む（MapLibre の compact。地図を動かすまでは開いている）。出典はメニューにも載せる
- 下のシート（詳細・知らせる・メニュー）は上に「つまみ」を付け、下に 80px 以上引くと閉じる
- OpenFreeMap の地名は「ローマ字＋日本語」の2段表示なので、読み込み後に `name:ja`（なければ `name`）だけを出すよう書き換える
- ボタンは指で押しやすい大きさ（高さ 44px 以上）にする

### 1.7 施設（地図の背景）

Google マップのように、拡大すると八代市の施設が種類の印と名前で見える。印は種類の色の丸（22px）に白いマーク（lucide の形）、名前は同じ系統の色。ピンが主役なので、印はピン（32px）より小さくして影を付けない（一文字の札は使わない。押しても何も起きない）。

| 種類 | 印 | 中身 | 出し始めるズーム |
|---|---|---|---|
| 買い物 | 青・買い物袋 | スーパー・コンビニ・薬局・物産館 | 14 |
| 医療 | 赤・十字 | 病院・保健センター・診療所 | 14 |
| 公共 | 灰・役所の建物 | 市役所・支所・公民館・コミュニティセンター | 14 |
| 給油 | 青緑・給油機 | ガソリンスタンド | 14 |
| 学校 | 茶・角帽 | 小中学校 | 15 |
| 公園 | 緑・木 | 公園・グラウンド | 15 |
| 飲食 | 橙・ナイフとフォーク | 飲食店・カフェ | 15 |
| 観光 | 紫・カメラ | 八代城跡などの観光施設 | 15 |

- 素材は `web/places.geojson`（485件。`python scripts/make_places.py` が作る）。入力は BODIK の八代市 公共施設・観光施設（CC BY 4.0）と OpenStreetMap（`data/osm`、ODbL）。同じ施設が両方にあるときは八代市の名前を残す
- 美容室・工場・居酒屋・服屋・団地・廃止された施設は出さない（災害時に探すものではなく、地図が混む）
- 印か名前が重なるところは丸ごと出さない（MapLibre の symbol の重なり判定）。背景の地図が元から出す施設（`poi_r*`）は消して一本化する。駅は残す
- 出典は地図の出典表示に「施設: © OpenStreetMap / 八代市 CC BY 4.0」を足す。`places.geojson` は OpenStreetMap を含むので ODbL に従う
- 施設の情報は取り込んだ時点のもの。災害時に開いているかはピンで伝える
- ピン（HTML の要素）は地図の上に重ねて描くので、施設の名前とは重なり判定をしない。ピンの下に施設の名前が少し見えることがある

## 2. API と DB の変更

DB の変更は `db/init.sql` を直接書き換える（公開前のため移行ツールは入れない）。開発中の DB は `docker compose down -v` で作り直す。

### 2.1 candidates（候補）

| 変更 | 内容 |
|---|---|
| `source` を追加 | `detected`（検知）/ `report`（利用者の報告） |
| 検知用の列を任意に | `cell_code`・`window_start`・`observed`・`expected`・`p_value` は `detected` のときだけ入る |
| `status` を変更 | `pending`（未確認）/ `confirmed`（確認済み）/ `ended`（終了） |
| `last_activity_at` を追加 | 最後に確認された時刻。種類の回答・報告・検知のたびに更新する（「わからない」「もう終わっていた」では更新しない） |

### 2.2 answers（回答）

- 1人1候補1件の「最新の意見」とする。同じ人が再び答えたら上書きする。種類の回答（`none`・`ended` 以外）のときだけ `last_activity_at` も更新する（§2.1 のとおり。409 は返さない）
- `kind` に `ended`（もう終わっていた）を追加する
  - `water` / `food` / `goods` / `car_sleeping` / `shelter` / `other` / `none`（わからない）/ `ended`
- `note`（備考）を追加する。100文字まで
- `id`（連番）を追加する。通報はこの番号で指す。備考を書いた人のセッション ID は外に出さない

### 2.3 確定と終了のルール

数値はすべて `app/` の1か所に定数としてまとめ、変えられるようにする。

| ルール | 内容 |
|---|---|
| 確認済み（検知の候補） | 種類（`none`・`ended` 以外）の回答が1人 |
| 確認済み（報告の候補） | 種類の回答が、報告者を含めて2人 |
| 終了 | 各人の最新の意見で「`ended` の数 ≧ 種類の回答の数」になったら `ended`（同数なら終了） |
| 薄く表示 | `last_activity_at` から3時間 |
| 表示しない | `last_activity_at` から6時間、または `ended` |
| 備考の非表示 | 通報が2件 |

- 検知と報告が重なったとき: 検知を 1 人ぶんの裏付けとして数え、報告の候補が確認済みになる（`app/detect_job.py`）

### 2.4 備考の検査（サーバー側）

- 100文字を超える、URL（`http://`・`https://`・`www.`）を含む、電話番号らしい数字の並びを含む場合は 422 を返す
- 備考は候補が表示されなくなると返さなくなる（DB からの削除は、セッションの失効と同じ定期処理で後から行う）

### 2.5 flags（通報）

- 新しい表: `flags(answer_id, session_id, created_at)`。1人1備考1回まで
- 通報2件で、その備考を API が返さなくなる

### 2.6 official_spots（公式拠点）

- 取り込み: 八代市の避難所は BODIK の GeoJSON（`scripts/import_bodik.py`）、他の地域の避難所・給水所は CSV（`scripts/import_official.py`、列は data/official/README.md）。`source` ごとに上書きするので、同じ CSV を入れ直しても重複しない

- 新しい表: `official_spots(id, source, source_key, name, address, kind, geom, opened_at, closed_at)`
  - `source` は取り込み元（`bodik-kumamoto-r8`）、`source_key` は取り込み元の中で一意なキー。BODIK のデータには ID がないため「市町村コード:名前」を使う。`(source, source_key)` を一意にする
- `scripts/import_bodik.py` が BODIK の GeoJSON（`https://odcs.bodik.jp/kumamoto-r8/data/portal/shelters.geojson`）をダウンロードして取り込む。同じデータを再び取り込んでも重複しない
- データの利用条件が確認できるまで、データ自体はリポジトリに入れない

### 2.7 API

| メソッド | パス | 変更 |
|---|---|---|
| GET | `/v1/spots?bbox=&at=` | 非公式（確認済み・未確認）と公式の避難所を1つの GeoJSON で返す。`properties` に `source`（`detected` / `report` / `official`）・`status`・`kinds`（種類ごとの回答数）・`last_activity_at`・`faded`（薄く表示するか）・`notes`（備考の一覧）を入れる。非公式には `candidate_id`・`top_kind`（一番多い種類）、公式には `official_id`・`kind`・`name`・`address`・`opened_at`・`closed_at` も入れる。`at` を付けると、その時点で開いていた避難所を返す（省略時は現在） |
| POST | `/v1/reports` | 新規。`{lat, lon, kind, note}`。100m 以内に表示中の非公式の候補があれば、その候補への回答として扱う。なければ `source=report` の候補を作る。どちらも作成・更新した候補の ID を返す |
| POST | `/v1/candidates/{id}/answers` | `note` を追加。上書き方式に変更（2回目も 201） |
| POST | `/v1/answers/{id}/flags` | 新規。備考の通報。同じ人の2回目は何もせず成功を返す |
| GET | `/v1/questions` | 変更なし（`source=report` の未確認ピンも対象になる） |

## 3. 配信・PWA・エラー時の動き・テスト

### 3.1 ファイル構成

```
web/index.html
web/app.js
web/style.css
web/manifest.webmanifest
web/icon.svg, web/icon-180.png, web/icon-192.png, web/icon-512.png   # PNG は iPhone のホーム画面・PWA 用
web/places.geojson                            # 地図の背景の施設（§1.7。scripts/make_places.py が作る）
scripts/import_bodik.py
scripts/check/ui-check.js, scripts/check/e2e-check.js     # 画面と通しの自動確認（Playwright）
```

- FastAPI が `/` で `web/` を配信する（API のルートより後に登録する）。API と同じサーバーなので CORS の設定は要らず、`ngrok http 18080` 1本で公開できる
- MapLibre GL は CDN から読み込む

### 3.2 PWA

- マニフェストとアイコンを置き、ホーム画面に追加できるようにする
- Service Worker（電波がないときにも画面を出す仕組み）は入れない。背景の地図が電波なしでは出ないため効果が小さい。「最後に見た拠点を電波なしで見る」機能を作るときに追加する

### 3.3 エラー時の動き

| 状況 | 画面の動き |
|---|---|
| 401（セッションが切れた・消えた） | 保存したトークンを消して、同意の画面に戻る |
| 通信できない | 位置は端末のメモリにためて、次に送れたときにまとめて送る（最大1000点、超えたら古い順に捨てる）。画面上部に「接続できません」と表示 |
| 位置の利用が許可されない | 同意の画面で「参加には今いる場所が必要です」と出て参加できない（対象地域の中にいる人だけが参加できるため）。対象地域の外なら「対象地域の外では参加できません」 |
| 参加したあとで位置が取れなくなった | 地図は見られる。「知らせる」ボタンは押せなくし、「今いる場所が必要です」と表示 |
| 422（備考が不正など） | 入力欄の下に理由を表示 |

### 3.4 テスト

API（実 DB に対して。`tests/test_api.py` と同じ方式）:
- 報告が新しい候補になる / 100m 以内なら既存の候補にまとまる
- 確認済みになる条件（検知は1人、報告は2人）
- 終了の多数決（同数なら終了）
- 回答の上書き
- 備考の検査（URL・電話番号・101文字で 422）
- 通報2件で備考が返らなくなる
- `at` で、その時点で開いていた避難所だけが返る
- 6時間たった候補が返らない

画面（`scripts/check/ui-check.js`。ヘッドレス Chromium でスマホの幅、15 項目。使い方はファイル冒頭）:
- 同意 → 地図が出る → 知らせる → オレンジのピンが立つ → 別のセッションから回答 → 紺のピンに変わる
- 「もう終わっていた」でピンが消える / 絞り込み / ダークモード / 位置を許可しない / 参加をやめる / 通信できない / 公式の避難所の詳細 / 現在地ボタン
- 近くに検知の候補のピンがあっても通るよう、自分が立てた候補は `data-candidate-id` で追い、公式のピンは要素を直接押す

通し（`scripts/check/e2e-check.js`）: 検知の候補の場所で画面を開く → 「近くで人が集まっています」→ 答える → 確認済み

## 4. この版に入れないもの

| もの | 入れるとき |
|---|---|
| 画面を閉じている間の通知（Web Push） | ネイティブアプリ化のとき |
| Service Worker（電波なしでの表示） | 最後に見た拠点を電波なしで見る機能を作るとき |
| 英語などの多言語表示 | 海外の利用者・貢献者が出てきたとき |
| 公式の給水拠点 | データの形式と利用条件が確認できたとき |
| 検知と報告が重なったときの確定 | 済（`app/detect_job.py`。検知を 1 人ぶんの裏付けに数える） |
| 失効したセッション・古い位置の DB からの削除 | 済（検知の定期処理が 30 日 / 14 日で消す） |
| 答える人の位置の確認（別のセッションで自分の報告を確かめる・遠くから「終わっていた」を押す、を防ぐ） | 済（回答に今の位置が要り、候補から 500m より遠いと 403。参加も対象地域 `AREA` の中の人だけ。docs/architecture.md §5.1） |
| 書き込みの回数制限 | 済（`app/ratelimit.py`。参加 20 回/時/IP、位置 10 回/分、回答・報告・通報 60 回/時） |

## 5. デモモード（`demo` ブランチ）
