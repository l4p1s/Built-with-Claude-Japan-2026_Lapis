# 行動の記入フォームの設計

## 目的

- 検知アルゴリズムを考え、精度を測るためのデータを自分たちで作る。その元になる「ある人の1日の行動」を、友人に記入してもらう
- 平常の日と災害の日（2026年7月の熊本地震の後）を**同じ人の対**で集める。検知は「その人がいつもは行かない場所」を数えるので、対になっていることが大事
- 住所を打たずに、地図をタップして「家はここ、次にここへ行って…」と直感的に入れられるようにする

## 全体の中での位置

| 段階 | 内容 | この文書 |
|---|---|---|
| 1 | 記入フォーム | 対象 |
| 2 | 変換: フォームの回答と Google マップのタイムラインの書き出しを、同じ「入った場所の一覧」に直す | 対象外 |
| 3 | 水増し: 筋書き（順番・場所の種類・時間帯・滞在の長さ）を残し、自宅と行き先を公開データから選び直す | 対象外 |
| 4 | 検知アルゴリズム: 3 のデータで考え、YJMob100K で確かめる | 対象外 |

Google マップのタイムラインが残っている友人は、その書き出しを使う（記録の方が正確）。残っていない友人の分をこのフォームで集める。両方を出してもらってもよい（タイムラインにない「何しに」「知ったきっかけ」を補える）。

## 決めたこと（要約）

| 項目 | 決定 |
|---|---|
| 入れ方 | 1画面に1問（Google フォームのよう）。場所は検索か地図の真ん中のピンで、家 → 次の場所 → … と直線でつなぐ。道順は入れない（段階3で道路沿いに補う） |
| 記入する日 | 「ふだんの日」と「地震の後の日」から始め、日付を選んで何日でも足せる |
| 届け方 | 最後に「コピーして LINE で送る」。サーバーには何も保存しない |
| 置き場所 | `docs/survey/index.html`。GitHub Pages（公開元: main の `/docs`）で公開 |
| 家の位置 | 小数3桁（約100m）に丸めてから保存・出力 |
| 書きかけ | ブラウザ（localStorage）に自動で保存し、開き直すと続きから書ける |
| 技術 | 本体と同じく HTML/JS を直接書く（ビルドなし）＋ MapLibre GL 6.16.0 ＋ OpenFreeMap |

---

## 1. 置き場所と公開

- ページは `docs/survey/index.html` の1ファイルで完結させる（HTML・CSS・JS を1つに入れる）。本体の `web/` は Pages の公開範囲の外なので参照できない。色と文字の決まり（`web/style.css` の `:root` の値）だけ写す
- 公開 URL: `https://l4p1s.github.io/Built-with-Claude-Japan-2026_Lapis/survey/`
- GitHub Pages の公開元を「main ブランチの `/docs`」に設定する（リポジトリの Settings → Pages）。これで `docs/` の設計書の md もページとして見られるようになるが、リポジトリはもともと公開なので新しく見えるものはない
- 今の API・DB・`web/` には手を入れない

## 2. 画面と操作

Google フォームのように、1画面に1問ずつ聞いて進む。スマホの縦画面を最優先にする。
上に進み具合の線と「いまどの日の何か所目か」、真ん中に問い、下に「戻る」「次へ」。

```
━━━━━━━━░░░░░░░            ← 進み具合
ふだんの日 7/20 ・ 2か所目
次に行った場所はどこですか？
名前で探すか、地図を動かして…
┌──────────────────┐
│ [🔍 場所の名前や住所で探す] │
│        📍  ← 真ん中のピン  │  ← 地図（残りの高さいっぱい）
│   家 ●──● 1           │
└──────────────────┘
[家に帰った]  家に帰らず、この日はここまで
[戻る] [　　　ここに行った　　　]
```

### 2.1 流れ

| 画面 | 問い | 入れ方 | 必須 |
|---|---|---|---|
| はじめに | ある1日に、どこへ行ったかを教えてください | 目的・LINE で送る・公開しない・家はぼかす、の説明と呼び名（20文字まで） | 呼び名 |
| 家 | 家はどこですか？ | 検索＋地図の真ん中のピン →「ここが家」 | − |
| 日付 | ふだんの日は／地震の後の日は、何月何日ですか？ | `<input type="date">`。ふだんの日は「地震の前の、いつもどおりの日」、地震の後の日は「給水や炊き出しに行った日があれば、その日」と添える | 日付 |
| 家を出た | その日、何時ごろ家を出ましたか？ | 時（0〜23）と分（00/15/30/45） | 時刻 |
| 場所 | 最初に／次に行った場所はどこですか？ | 検索＋地図の真ん中のピン →「ここに行った」。下に「家に帰った」と「家に帰らず、この日はここまで」 | − |
| 種類 | そこは何ですか？ | 種類・場所の名前・ふだんも行くか（2.3） | 種類・ふだんも |
| 時刻 | 何時ごろ着いて、どのくらいいましたか？ | 2.4 | 着いた・出た |
| 家に帰った | 何時ごろ家に帰りましたか？ | 時と分。家にいるのは24時まで | 時刻 |
| 見直し | この日の動きを確かめてください | 地図（点と線）・1日の帯・場所の一覧。押すとその場所を直せる | − |
| ほかの日 | ほかの日も書きますか？ | 「はい、もう1日書く」「いいえ、送る」 | − |
| 送る | 送る | 2.6 | − |

- 日ごとに「日付 → 家を出た → 場所・種類・時刻のくり返し → 家に帰った → 見直し」。ふだんの日の見直しの次は地震の後の日、そのあとは「ほかの日」
- 「家に帰らず、この日はここまで」は、車中泊や避難所に泊まった日のため。最後の場所の出た時刻を翌朝にして終える
- 「次へ」を押したときに必須が抜けていれば進まず、その項目を赤い地・左の赤い線・「未入力」で知らせ、そこまでスクロールする（選択欄そのものにはフォーカスしない。スマホで選択の画面が勝手に開かないように）
- 「戻る」で1問ずつ戻れる。戻って場所を置き直すと、その場所が動く（新しく足さない）。戻った先で「家に帰った」を押すと、その先に書いた場所は確認のうえ消す
- 見直しから直したときは、「次へ」で見直しに戻る。見直しの「次へ」は、未入力の場所が残っていればその場所を開く
- 足した日は、その日の日付の画面で「この日を消す」
- 使い方の案内（以前の9段の案内）はなくした。1画面に1問なので、問いを読めば何をすればよいか分かる

### 2.2 地図と検索
- 地図は「家」「場所」「見直し」の画面だけに出す。家と場所の画面では、地図を残りの高さいっぱいに出す
- 地図の真ん中に、いつもピンを立てておく（ピンの先が地図の中心）。地図を指で動かすか、タップした所へ地図が動いてピンが合う
- 場所の画面では、それまでに決めた場所を点（家・1・2…）と点線で出す。地図は前の場所から始める
- 検索欄は地図の上に浮かべる。入力が止まって0.4秒後（2文字以上）か、検索キーで探す
- 店や施設の名前は Photon（OpenStreetMap をもとにした検索。今見ている地図の中心の近くを優先）、住所と町名は国土地理院の地名検索。両方に同時に聞き、Photon 5件 → 国土地理院 5件の順に並べる。どちらも鍵なしで使える
- 候補を選ぶと地図がそこへ動き、真ん中のピンが合う。そのまま「ここに行った」を押すと（選んだ場所から30m以内）、その名前を「場所の名前」に入れておく
- 見つからないときは「近くの町名や目印で探すか、地図をタップしてください」、通信できないときは「検索できませんでした」と出す
- 限界: OpenStreetMap に載っていない店や施設は見つからない。検索した言葉は Photon と国土地理院に送られる
- 地図の出典表示に「検索: Photon・国土地理院」を足す
- 家の位置は約100mに丸め、すべての日の「自宅」を同じ位置にする。地図の初期位置は八代市の中心（本体の `web/app.js` の START と同じ）

### 2.3 種類の画面
| 項目 | 入れ方 | 必須 |
|---|---|---|
| 種類 | 自宅 / 職場・学校 / 店 / 給水 / 炊き出し / 避難所 / 車中泊 / 知人の家 / その他 | 必須 |
| 場所の名前・くわしく | 種類を選ぶと、すぐ下に出る1行の欄（50文字まで、自宅は出さない）。例文は種類ごと（店なら「例: ○○スーパー八代店」） | 任意 |
| ふだんも行くか | はい / いいえ | 必須 |
| 何しに | 自由に1行（50文字まで） | 任意（「くわしく（任意）」の中） |
| 知ったきっかけ | お隣さん / インスタ / LINE / 張り紙 / 通りがかり / いつも行く / その他 | 任意（同上） |
| そこまでの移動手段 | 徒歩 / 車 / 自転車 / その他 | 任意（同上） |

- 「この場所を消す」（確認あり）

### 2.4 時刻の画面
- 「何時ごろ着いた？」を時と分で選び、「どのくらいいた？」を 15分 / 30分 / 1時間 / 2時間 / 3時間 / それ以上… のボタンで選ぶ。「それ以上…」で「何時ごろ出た？」を直接選べる
- 着いた時刻の既定値は、前の場所の出た時刻
- 着いた時刻を直したときは、選んでいた長さを保って出た時刻を計算し直す
- どの順番で選んでもよい。「時」より先に選んだ「分」は残し、着いた時刻より先に選んだ長さは覚えておいて、着いた時刻を選んだときに出た時刻を計算する
- 選択欄の値は画面を開いたときだけ入れる（選んでいる最中に入れ直さない）
- 出た時刻が着いた時刻より前なら翌日までとみなし、「翌日の 6:00 まで」と出す（夜をまたぐ車中泊など）
- 前の場所を出る前に着いていたら「時刻が前の場所と重なっています」と出す。進むのは止めない

### 2.5 見やすさ（50代の人でも入力しやすく）
- 文字は本文 17px、問い 21px、項目名 16px（太字・濃い色）。薄い灰色の小さな文字は使わない
- ボタン・入力欄の高さは 48〜52px。押せる部品の枠は濃いめの線（`--line`）
- 選ぶものはプルダウンでなく大きなボタンを並べ、選んだものは紺で塗って ✓ を付ける。任意の項目は、もう一度押すと外せる
- 入力するところは、うすい紺の地（`--input`）にして説明の文字と区別する
- 1日の帯: 0時から24時に滞在を並べ、入っていない時間はうすい斜線。色は種類ごとにしない

### 2.6 送る
- 日ごとの件数と、未入力の場所の数を出す
- 「コピーして LINE で送る」: 回答の JSON を `navigator.clipboard.writeText` でコピーし、「コピーしました。LINE に貼り付けて送ってください」と出す
- コピーできない端末のために、同じ JSON を選択しやすい欄（`<textarea readonly>`）にも出す
- 「この端末から消す」: 書きかけの保存を消す（確認あり）

## 3. 回答のデータ

```json
{"v":1,"name":"A","home":[32.507,130.602],
 "days":[
  {"label":"ふだんの日","date":"2026-07-20","stays":[
    {"lat":32.507,"lon":130.602,"from":"00:00","to":"07:45","type":"home","usual":true},
    {"lat":32.51234,"lon":130.60111,"from":"08:00","to":"08:30","type":"shop",
     "purpose":"朝ごはん","heard":"usual","usual":true,"mode":"car"}]},
  {"label":"地震の後の日","date":"2026-07-30","stays":[]}]}
```

| キー | 値 |
|---|---|
| v | 形式の版。今は 1 |
| name | 呼び名 |
| home | 家の位置 [緯度, 経度]、小数3桁 |
| days[].label / date | 「ふだんの日」か「地震の後の日」/ `YYYY-MM-DD`（未入力なら null） |
| stays[].lat, lon | 小数5桁（約1m）。種類が home のときは home と同じ値 |
| stays[].from, to | `HH:MM`。to < from は翌日まで |
| stays[].type | home / work / shop / water / food / shelter / car_sleeping / friend / other |
| stays[].detail | 場所の名前・くわしく。文字列か省略（家には付けない） |
| stays[].purpose | 文字列か省略 |
| stays[].heard | neighbor / instagram / line / poster / passing / usual / other か省略 |
| stays[].usual | true / false |
| stays[].mode | walk / car / bicycle / other か省略 |

- 種類のキーは、本体の `app/rules.py` の Kind（water / food / shelter / car_sleeping / other）と重なるものは同じ名前にする
- JSON は空白なしで出す（LINE に貼る文字数を減らすため）

## 4. 書きかけの保存

- 入力のたびに回答の JSON と、いまの画面（送る内容には入らない）を `localStorage` に保存し、開き直すとその画面から続ける
- `localStorage` が使えない（プライベートモードなど）ときは保存せずに動く（try/catch）
- 送ったあとも自動では消さない（送り直せるように）。「この端末から消す」で消す

## 5. プライバシーと扱い

- サーバーには何も送らない。地図のタイル（OpenFreeMap）を読むときに、表示している範囲がタイルの配信元に伝わるのは本体と同じ
- 家の位置は丸めてから保存・出力する。丸める前の値はどこにも残さない
- 受け取った回答（JSON）はリポジトリに入れない。段階2以降で使い、公開するのは水増しした後のデータだけ
- 回答してくれた人から「やめたい」と言われたら、受け取った回答と、それから作ったデータを消す

## 6. 先に伝える限界

- 思い出して書くので、時刻と場所はタイムラインの記録より粗い
- 道順は入らない。場所と場所の間は段階3で補う
- LINE の1通に入る文字数には上限がある。長めの回答（3日 × 各10か所）で実際に送れるか確かめ、入らなければ「ファイルで保存」ボタン（JSON のダウンロード）を足す

## 7. 確認のしかた

- ヘッドレスの Chromium（`scripts/ui-check.js` と同じ道具）で次の流れを `scripts/survey-check.js` で確かめる（検索は決まった答えに差し替える）:
  1. はじめに: 呼び名がないと赤で知らせ、入れると進む
  2. 家: 名前で探して、真ん中のピンで決める。地図が大きく出る
  3. ふだんの日: 日付 → 家を出た → 2か所（種類・時刻をどの順でも）→ 家に帰った
  4. 見直し: 帯と一覧が出て、押すと直せ、戻るで1問ずつ戻れる
  5. 地震の後の日: 家に帰らない日（車中泊で翌朝まで）も書ける
  6. 送る: JSON が §3 の形で、家が小数3桁。コピーできる
  7. 日を足せて消せる。開き直すと続きから。「この端末から消す」で最初に戻る
  8. Console にエラーがなく、360px 幅で横にはみ出さない
- 390×844 と 360×740（ダークモード）のスクリーンショットを目で見て、崩れていないことを確かめる
