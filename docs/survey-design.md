# 行動の記入フォームの設計

## 目的

- 検知アルゴリズムを考え、精度を測るためのデータを自分たちで作る。その元になる「ある人の1日の行動」を、友人に記入してもらう
- 平常の日と災害の日（2026年7月の熊本地震の後）を**同じ人の対**で集める。検知は「その人がいつもは行かない場所」を数えるので、対になっていることが大事
- 住所を打たずに、地図をタップして「家はここ、次にここへ行って…」と直感的に入れられるようにする

## 全体の中での位置

| 段階 | 内容 | この文書 |
|---|---|---|
| 1 | 記入フォーム | 対象 |
| 2 | 変換: フォームの回答と Google マップのタイムラインの書き出しを、同じ「入った場所の一覧」に直す | 対象外 |
| 3 | 水増し: 筋書き（順番・場所の種類・時間帯・滞在の長さ）を残し、自宅と行き先を公開データから選び直す | 対象外 |
| 4 | 検知アルゴリズム: 3 のデータで考え、YJMob100K で確かめる | 対象外 |

Google マップのタイムラインが残っている友人は、その書き出しを使う（記録の方が正確）。残っていない友人の分をこのフォームで集める。両方を出してもらってもよい（タイムラインにない「何しに」「知ったきっかけ」を補える）。

## 決めたこと（要約）

| 項目 | 決定 |
|---|---|
| 入れ方 | 1画面に1問（Google フォームのよう）。場所は検索か地図の真ん中のピンで、家 → 次の場所 → … と直線でつなぐ。道順は入れない（段階3で道路沿いに補う） |
| 記入する日 | いつもの平日・いつもの休日（特定の日でなく、地震の前のいつもの動き。日付は聞かない）・地震の日・地震の後の日の4日。「追加の日」として何日でも足せる。地震の日からは「いつもと同じ」なら写して、違うところだけ直す（2026-11-04、回答者の「3か月前を思い出すのが大変」「被災したところ以外はいつもと同じ」を受けて） |
| 届け方 | 最後に「送信する」。発案者の Google スプレッドシートに Google Apps Script で集め、回答を見るページ（`docs/survey/view.html`、合言葉が必要）で地図と帯で見る。自前のサーバーは使わない（§8） |
| 置き場所 | `docs/survey/index.html`（記入）・`view.html`（見る）・`common.js`（送り先の URL と共通の部品）。GitHub Pages（公開元: `survey` ブランチの `/docs`）で公開 |
| 家の位置 | 小数3桁（約100m）に丸めてから保存・出力 |
| 書きかけ | ブラウザ（localStorage）に自動で保存し、開き直すと続きから書ける |
| 技術 | 本体と同じく HTML/JS を直接書く（ビルドなし）＋ MapLibre GL 6.16.0 ＋ 国土地理院の地図（標準地図・航空写真） |

## 1. 置き場所と公開

- ページは `docs/survey/index.html` の1ファイルで完結させる（HTML・CSS・JS を1つに入れる）。本体の `web/` は Pages の公開範囲の外なので参照できない。色と文字の決まり（`web/style.css` の `:root` の値）だけ写す
- 公開 URL: `https://l4p1s.github.io/Built-with-Claude-Japan-2026_Lapis/survey/`
- GitHub Pages の公開元は「`survey` ブランチの `/docs`」（リポジトリの Settings → Pages）。main を整理したとき（2026-11-05）に記入フォームを main から外したので、公開元もこのブランチに移した。`docs/` の設計書の md もページとして見られるが、リポジトリはもともと公開なので新しく見えるものはない
- 今の API・DB・`web/` には手を入れない

## 2. 画面と操作

Google フォームのように、1画面に1問ずつ聞いて進む。スマホの縦画面を最優先にする。
上に進み具合の線と「いまどの日の何か所目か」、真ん中に問い、下に「戻る」「次へ」。

```
━━━━━━━━░░░░░░░            ← 進み具合
地震の日 7/27 ・ 2か所目
次に行った場所はどこですか？
名前で探すか、地図を動かして…
┌──────────────────┐
│ [🔍 場所の名前や住所で探す] │
│        📍  ← 真ん中のピン  │  ← 地図（残りの高さいっぱい）
│   家 ●──● 1           │
└──────────────────┘
[家に帰った]  家に帰らず、この日はここまで
[戻る] [　　　ここに行った　　　]
```

### 2.1 流れ

| 画面 | 問い | 入れ方 | 必須 |
|---|---|---|---|
| はじめに | ある1日に、どこへ行ったかを教えてください | 目的・最後に送信する・公開しない・家はぼかす、の説明と呼び名（20文字まで） | 呼び名 |
| 家 | 家はどこですか？ | 検索＋地図の真ん中のピン →「ここが家」 | − |
| 日付 | 地震の日は／…、何月何日ですか？（いつもの平日・休日では聞かない） | `<input type="date">`。地震の日は「地震が起きた日」、地震の後の日は「給水や炊き出しに行った日があれば、その日」、追加の日は「書いておきたい日」と添える | 日付 |
| いつもと同じ？ | この日の動きは、いつもと同じでしたか？（日付のあと） | 「いつもの平日と同じ」「いつもの休日と同じ」→ その日の動きを写して見直しへ。「違った」→ 家を出た時刻から聞く | − |
| 家を出た | その日、何時ごろ家を出ましたか？（いつもの日は「いつもの平日は、何時ごろ家を出ますか？」。場所・時刻・帰った時刻の問いも、いつもの日は「〜しますか」にする） | 時（0〜23）と分（00/15/30/45）。いつもの日は「日によって違うときは、いちばん多いときで」と添える | 時刻 |
| 場所 | 最初に／次に行った場所はどこですか？ | 検索＋地図の真ん中のピン →「ここに行った」。下に「家に帰った」と「家に帰らず、この日はここまで」 | − |
| 種類 | そこは何ですか？ | 種類・場所の名前・ふだんも行くか（2.3） | 種類・ふだんも |
| 時刻 | 何時ごろ着いて、どのくらいいましたか？ | 2.4 | 着いた・出た |
| 家に帰った | 何時ごろ家に帰りましたか？ | 時と分。家にいるのは24時まで | 時刻 |
| 見直し | この日の動きを確かめてください | 地図（点と線）・1日の帯・場所の一覧。押すとその場所を直せる。「場所を足す」で抜けた場所を足せる | − |
| ほかの日 | ほかの日も書きますか？ | 「はい、もう1日書く」「いいえ、送る」 | − |
| 送る | 送る | 2.6 | − |

- 日ごとに「（日付 → いつもと同じ？）→ 家を出た → 場所・種類・時刻のくり返し → 家に帰った → 見直し」。4日を順に書き、地震の後の日の見直しの次は「ほかの日」。「はい、もう1日書く」で「追加の日」を足す（地震の前か後かは日付で分かる）
- 「家に帰らず、この日はここまで」は、車中泊や避難所に泊まった日のため。最後の場所の出た時刻を翌朝にして終える
- 「家に帰った」を押さずに、次の場所を家に合わせて種類で「自宅」を選んでもよい（2026-11-04、回答者が「次 自宅」で赤くなり進めなかったため）。そのときは種類の下に「帰ったあと出かけなかったら、次の画面の『このあとは出かけない』を押してください」と出し、時刻の画面の長さに「このあとは出かけない」（家に24時までいる）を足す。押すとその日はここまでで、見直しへ進む（「家に帰った」と同じ形のデータになる）
- 「次へ」を押したときに必須が抜けていれば進まず、その項目を赤い地・左の赤い線・「未入力」で知らせ、そこまでスクロールする（選択欄そのものにはフォーカスしない。スマホで選択の画面が勝手に開かないように）
- 「戻る」で1問ずつ戻れる。戻って場所を置き直すと、その場所が動く（新しく足さない）。戻った先で「家に帰った」を押すと、その先に書いた場所は確認のうえ消す
- 見直しから直すときは「場所 → 種類 → 時刻」と進み、「次へ」で見直しに戻る（場所の画面のボタンは「ここに決める」、「家に帰った」は出さない）。見直しの「次へ」は、未入力の場所が残っていればその場所を開く
- 見直しを開くたびに、家を出た → 場所（着いた時刻の順）→ 家に帰った、に並べ直す（足した場所が正しい位置に入るように）。0時を過ぎてから着いた場所は先頭に来てしまう（そういう回答が出たら直す）
- 写した日で「戻る」を押すと「いつもと同じ？」に戻る。そこで同じ方をもう一度押しても写し直さない（直したところを残す）。別の方を押すと確認して写し直し、「違った」を押すと写したものを消して1問ずつ聞く
- 足した日は、その日の日付の画面で「この日を消す」（最初の4日は消せない）

### 2.1b 画面の紹介
- 画面の種類ごとに、初めて出たとき、その画面の使い方を順に紹介する。説明する場所だけを明るく抜き、その近くに説明のカードを出す。「次へ」で次の段、最後は「わかった」。「とばす」・Esc で閉じる
- はじめに（このページについて・進み具合・?・次へ）、家（検索・真ん中のピン・ここが家）、日付、家を出た、場所（ピン・ここに行った・家に帰った／この日はここまで）、種類（種類・ふだんも・くわしく）、時刻（着いた・いた長さ）、家に帰った、見直し（地図・帯・一覧・次へ）、ほかの日、送る（コピー・消す）
- 2つ目の場所や2日目など、同じ種類の画面には出さない（くり返すと答えるのが遅くなるため）。どの画面で見終わったかは書きかけと一緒に保存する（送る内容には入らない）
- 右上の ? で、いま出ている画面の紹介をいつでも見直せる

### 2.2 地図と検索
- 地図は「家」「場所」「見直し」の画面だけに出す。家と場所の画面では、地図を残りの高さいっぱいに出す
- 地図の真ん中に、いつもピンを立てておく（ピンの先が地図の中心）。地図を指で動かすか、タップした所へ地図が動いてピンが合う
- 地図は国土地理院の標準地図（学校の「文」、病院、郵便局、神社・寺、町名、建物の形などの目印が載る）。右下の「写真」で航空写真に切り替えられる（屋根や駐車場の形で家を探せる）。もう一度押すと地図に戻る
- 限界: 国土地理院の地図には店の名前は載らない（店は名前で検索する）。暗い色の版がないので、ダークモードでも地図は明るいまま（点線は濃い紺）
- 場所の画面では、それまでに決めた場所を点（家・1・2…）と点線で出す。地図は前の場所から始める
- 検索欄は地図の上に浮かべる。入力が止まって0.4秒後（2文字以上）か、検索キーで探す
- 店や施設の名前は Photon（OpenStreetMap をもとにした検索。今見ている地図の中心の近くを優先）、住所と町名は国土地理院の地名検索。両方に同時に聞き、Photon 5件 → 国土地理院 5件の順に並べる。どちらも鍵なしで使える
- 候補を選ぶと地図がそこへ動き、真ん中のピンが合う。そのまま「ここに行った」を押すと（選んだ場所から30m以内）、その名前を「場所の名前」に入れておく
- 見つからないときは「近くの町名や目印で探すか、地図をタップしてください」、通信できないときは「検索できませんでした」と出す
- 限界: OpenStreetMap に載っていない店や施設は見つからない。検索した言葉は Photon と国土地理院に送られる
- 地図の出典表示は「国土地理院」と「検索: Photon・国土地理院」
- 家の位置は約100mに丸め、すべての日の「自宅」を同じ位置にする。地図の初期位置は八代市の中心（本体の `web/app.js` の START と同じ）

### 2.3 種類の画面
| 項目 | 入れ方 | 必須 |
|---|---|---|
| 種類 | 自宅 / 職場・学校 / 店 / 給水 / 炊き出し / 避難所 / 車中泊 / 知人の家 / その他 | 必須 |
| 場所の名前・くわしく | 種類を選ぶと、すぐ下に出る欄（100文字まで、自宅は出さない）。例文は種類ごと（店なら「例: ○○スーパー八代店」） | 任意 |
| ふだんも行くか | はい / いいえ | 必須 |
| 何しに | 自由に書く（200文字まで） | 任意（「くわしく（任意）」の中） |
| 知ったきっかけ | お隣さん / インスタ / LINE / 張り紙 / 通りがかり / いつも行く / その他 | 任意（同上） |
| そこまでの移動手段 | 徒歩 / 車 / 自転車 / その他 | 任意（同上） |

- 「場所の名前・くわしく」と「何しに」は、折り返して全部見える欄（`<textarea>`）にし、書いた分だけ縦に伸ばす。1行の欄だとスマホで文が横に流れて読み返せず、直しにくかったため（2026-11-04、回答者から）。1文字ごとに保存する
- 「この場所を消す」（確認あり）

### 2.4 時刻の画面
- 「何時ごろ着いた？」を時と分で選び、「どのくらいいた？」を 15分 / 30分 / 1時間 / 2時間 / 3時間 / それ以上… のボタンで選ぶ。「それ以上…」で「何時ごろ出た？」を直接選べる
- 着いた時刻の既定値は、前の場所の出た時刻
- 着いた時刻を直したときは、選んでいた長さを保って出た時刻を計算し直す
- どの順番で選んでもよい。「時」より先に選んだ「分」は残し、着いた時刻より先に選んだ長さは覚えておいて、着いた時刻を選んだときに出た時刻を計算する
- 選択欄の値は画面を開いたときだけ入れる（選んでいる最中に入れ直さない）
- 出た時刻が着いた時刻より前なら翌日までとみなし、「翌日の 6:00 まで」と出す（夜をまたぐ車中泊など）
- 前の場所を出る前に着いていたら「時刻が前の場所と重なっています」と出す。進むのは止めない

### 2.5 見やすさ（50代の人でも入力しやすく）
- 文字は本文 17px、問い 21px、項目名 16px（太字・濃い色）。薄い灰色の小さな文字は使わない
- ボタン・入力欄の高さは 48〜52px。押せる部品の枠は濃いめの線（`--line`）
- 選ぶものはプルダウンでなく大きなボタンを並べ、選んだものは紺で塗って ✓ を付ける。任意の項目は、もう一度押すと外せる
- 入力するところは、うすい紺の地（`--input`）にして説明の文字と区別する
- 1日の帯: 0時から24時に滞在を並べ、入っていない時間はうすい斜線。色は種類ごとにしない

### 2.6 送信する
- 日ごとの場所の数（家は数えない）と、未入力の場所の数を出す
- 「送信する」: 回答の JSON を送り先（§8）に POST する。本文は text/plain のまま送る（ブラウザが事前の確認の通信をしないので、Apps Script でも受けられる）
- 送れたら「送信しました。ありがとうございました。直したときは、もう一度送信すると前の回答に上書きされます」。送信した日時は書きかけと一緒に保存し、開き直すと「○○に送信済みです」と出す
- 送れなかったら「送信できませんでした。電波のよいところで、もう一度押してください。書いた内容は消えていません」
- 「この端末から消す」: 書きかけの保存を消す（確認あり。送った内容は消えない）
- LINE で送る形（コピー）は、やめた

## 3. 回答のデータ

```json
{"v":1,"cid":"0f8fad5b-d9cb-469f-a165-70867728950e","name":"A","home":[32.507,130.602],
 "days":[
  {"label":"いつもの平日","date":null,"stays":[
    {"lat":32.507,"lon":130.602,"from":"00:00","to":"07:45","type":"home","usual":true},
    {"lat":32.51234,"lon":130.60111,"from":"08:00","to":"08:30","type":"shop",
     "purpose":"朝ごはん","heard":"usual","usual":true,"mode":"car"}]},
  {"label":"いつもの休日","date":null,"stays":[]},
  {"label":"地震の日","date":"2026-07-27","copied_from":"いつもの平日","stays":[]},
  {"label":"地震の後の日","date":"2026-07-30","stays":[]}]}
```

| キー | 値 |
|---|---|
| v | 形式の版。今は 1 |
| cid | 端末ごとの番号（`crypto.randomUUID()`）。送り直したときに前の回答へ上書きするために使う |
| name | 呼び名 |
| home | 家の位置 [緯度, 経度]、小数3桁 |
| days[].label / date | 「いつもの平日」「いつもの休日」「地震の日」「地震の後の日」「追加の日」/ `YYYY-MM-DD`（いつもの日と未入力は null） |
| days[].copied_from | 「いつもの平日」か「いつもの休日」。「いつもと同じ」で写した日だけ付く（写したあとに直していてもよい）。本人が1問ずつ書いた日と区別するため |
| stays[].lat, lon | 小数5桁（約1m）。種類が home のときは home と同じ値 |
| stays[].from, to | `HH:MM`。to < from は翌日まで |
| stays[].type | home / work / shop / water / food / shelter / car_sleeping / friend / other |
| stays[].detail | 場所の名前・くわしく。文字列か省略（家には付けない） |
| stays[].purpose | 文字列か省略 |
| stays[].heard | neighbor / instagram / line / poster / passing / usual / other か省略 |
| stays[].usual | true / false |
| stays[].mode | walk / car / bicycle / other か省略 |

- 種類のキーは、本体の `app/rules.py` の Kind（water / food / shelter / car_sleeping / other）と重なるものは同じ名前にする
- JSON は空白なしで送る

## 4. 書きかけの保存

- 入力のたびに回答の JSON と、いまの画面・紹介を見終わった画面・送信した日時（どれも送る内容には入らない）を `localStorage` に保存し、開き直すとその画面から続ける
- `localStorage` が使えない（プライベートモードなど）ときは保存せずに動く（try/catch）
- 送ったあとも自動では消さない（送り直せるように）。「この端末から消す」で消す

## 5. プライバシーと扱い

- 回答は発案者の Google アカウントのスプレッドシートにだけ溜まる。読めるのは、そのアカウントと、合言葉を知っている人（回答を見るページ）だけ
- 地図のタイル（国土地理院）を読むときに、表示している範囲がタイルの配信元に伝わる
- 家の位置は丸めてから保存・出力する。丸める前の値はどこにも残さない
- 受け取った回答（JSON）はリポジトリに入れない。段階2以降で使い、公開するのは水増しした後のデータだけ
- 回答してくれた人から「やめたい」と言われたら、スプレッドシートのその人の行と、それから作ったデータを消す

## 6. 先に伝える限界

- 思い出して書くので、時刻と場所はタイムラインの記録より粗い
- 道順は入らない。場所と場所の間は段階3で補う
- 送り先の URL はページに書いてあるので、誰でも送れる。形と大きさ（45,000文字まで）は確かめるが、でたらめな回答が混ざることはありうる。見るページで呼び名と中身を見て、知らないものは消す
- 1つの回答は 45,000 文字まで（スプレッドシートの1つのセルの上限 50,000 文字より少なく）。4日で場所を合わせて 40か所ほどなら 1万文字以下

## 7. 確認のしかた

- ヘッドレスの Chromium（`scripts/ui-check.js` と同じ道具）で次の流れを `scripts/survey-check.js` で確かめる（検索は決まった答えに差し替える）:
  0. 開いてすぐ紹介が出て、? で見直せ、とばせる。紹介は画面の種類ごとに1回だけ
  1. はじめに: 呼び名がないと赤で知らせ、入れると進む
  2. 家: 名前で探して、真ん中のピンで決める。地図が大きく出る
  3. いつもの平日: 日付なしで、家を出た → 2か所（種類・時刻をどの順でも）→ 家に帰った
  4. 見直し: 帯と一覧が出て、押すと直せ、戻るで1問ずつ戻れる
  5. いつもの休日。地震の日は「いつもの平日と同じ」で写して場所を1つ足す（時刻の順に並ぶ）。地震の後の日は「違った」で1問ずつ、家に帰らない日（車中泊で翌朝まで）も書ける
  6. 送信: 失敗したら知らせ、もう一度押せる。送った JSON が §3 の形で、家が小数3桁。開き直すと送信済みと出る
  7. 日を足せて消せる。開き直すと続きから。「この端末から消す」で最初に戻る
  8. 360px 幅で横にはみ出さない
  9. 回答を見るページ: 合言葉が違うと読めない。人と日を選ぶと地図・帯・表に出る。まとめて保存できる
  10. Console にエラーがない
- 390×844 と 360×740（ダークモード）のスクリーンショットを目で見て、崩れていないことを確かめる

## 8. 回答の集め方（Google スプレッドシート）

```
記入ページ ──送信（POST, 回答）──→ Apps Script ──→ スプレッドシート「回答」シート（1人1行）
見るページ ──POST {list, 合言葉}──→ Apps Script ──→ 全員分の回答
```

- プログラムは `scripts/survey-collect.gs`。送り直し（同じ cid）は同じ行を上書きする。合言葉はスクリプトのプロパティ `VIEW_KEY` に置き、リポジトリやページには書かない
- シートの列: 端末 / 呼び名 / 受け取った日時 / 日数 / 場所の数 / 回答（JSON）
- 回答を見るページ（`docs/survey/view.html`）: 合言葉を入れると、回答した人の一覧（新しい順）と、選んだ人・日の地図（点と点線）・1日の帯・表を出す。ふだんは行かない場所は紺。「まとめて保存」で全員分を JSON で手元に保存する（リポジトリには入れない）。合言葉はタブを閉じるまで覚える
- 回答を消すときは、スプレッドシートの行を消す

### 設定のしかた（発案者が1回だけ行う）
1. Google ドライブで新しいスプレッドシートを作る（名前は何でもよい）
2. メニューの「拡張機能」→「Apps Script」を開き、最初からある中身を消して `scripts/survey-collect.gs` の中身を貼り、保存する
3. 左の歯車（プロジェクトの設定）→ いちばん下の「スクリプト プロパティ」→「スクリプト プロパティを追加」で、プロパティ `VIEW_KEY`、値に合言葉（人に推測されない長めの文字列）を入れて保存する
4. 右上の「デプロイ」→「新しいデプロイ」→ 種類の歯車で「ウェブアプリ」を選ぶ。「次のユーザーとして実行」は「自分」、「アクセスできるユーザー」は「全員」にして「デプロイ」
5. 初回は権限の確認が出る。自分のアカウントを選び、「詳細」→「（プロジェクト名）に移動」→「許可」
6. 出てきた「ウェブアプリの URL」（`https://script.google.com/macros/s/…/exec`）を、`docs/survey/common.js` の `ENDPOINT` に入れて公開する
- `survey-collect.gs` を直したときは、「デプロイ」→「デプロイを管理」→ 鉛筆 →「バージョン: 新バージョン」で出し直す（URL は変わらない）
- Node で動きを確かめる: `node scripts/survey-collect-check.js`（Google のサービスを差し替えて、送信・上書き・形の確認・大きさの上限・合言葉を見る）
