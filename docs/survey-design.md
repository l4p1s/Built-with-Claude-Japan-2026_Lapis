# 行動の記入フォームの設計

## 目的

- 検知アルゴリズムを考え、精度を測るためのデータを自分たちで作る。その元になる「ある人の1日の行動」を、友人に記入してもらう
- 平常の日と災害の日（2026年7月の熊本地震の後）を**同じ人の対**で集める。検知は「その人がいつもは行かない場所」を数えるので、対になっていることが大事
- 住所を打たずに、地図をタップして「家はここ、次にここへ行って…」と直感的に入れられるようにする

## 全体の中での位置

| 段階 | 内容 | この文書 |
|---|---|---|
| 1 | 記入フォーム | 対象 |
| 2 | 変換: フォームの回答と Google マップのタイムラインの書き出しを、同じ「入った場所の一覧」に直す | 対象外 |
| 3 | 水増し: 筋書き（順番・場所の種類・時間帯・滞在の長さ）を残し、自宅と行き先を公開データから選び直す | 対象外 |
| 4 | 検知アルゴリズム: 3 のデータで考え、YJMob100K で確かめる | 対象外 |

Google マップのタイムラインが残っている友人は、その書き出しを使う（記録の方が正確）。残っていない友人の分をこのフォームで集める。両方を出してもらってもよい（タイムラインにない「何しに」「知ったきっかけ」を補える）。

## 決めたこと（要約）

| 項目 | 決定 |
|---|---|
| 入れ方 | 地図をタップして、家 → 次の場所 → … と直線でつなぐ。道順は入れない（段階3で道路沿いに補う） |
| 記入する日 | 「ふだんの日」と「地震の後の日」から始め、日付を選んで何日でも足せる |
| 届け方 | 最後に「コピーして LINE で送る」。サーバーには何も保存しない |
| 置き場所 | `docs/survey/index.html`。GitHub Pages（公開元: main の `/docs`）で公開 |
| 家の位置 | 小数3桁（約100m）に丸めてから保存・出力 |
| 書きかけ | ブラウザ（localStorage）に自動で保存し、開き直すと続きから書ける |
| 技術 | 本体と同じく HTML/JS を直接書く（ビルドなし）＋ MapLibre GL 6.16.0 ＋ OpenFreeMap |

## 1. 置き場所と公開

- ページは `docs/survey/index.html` の1ファイルで完結させる（HTML・CSS・JS を1つに入れる）。本体の `web/` は Pages の公開範囲の外なので参照できない。色と文字の決まり（`web/style.css` の `:root` の値）だけ写す
- 公開 URL: `https://l4p1s.github.io/Built-with-Claude-Japan-2026_Lapis/survey/`
- GitHub Pages の公開元を「main ブランチの `/docs`」に設定する（リポジトリの Settings → Pages）。これで `docs/` の設計書の md もページとして見られるようになるが、リポジトリはもともと公開なので新しく見えるものはない
- 今の API・DB・`web/` には手を入れない

## 2. 画面と操作

スマホの縦画面を最優先にする。上から順に、日のタブ・地図・1日の帯・カード。

```
┌───────────────────────────────┐
│ ふだんの日 │[地震の後の日]│ ＋ │  ← 日のタブ
├───────────────────────────────┤
│      ①家 ●                    │
│           ╲                   │  ← 地図
│            ●──────● ②スーパー │
│                    ╲          │
│                     ● ③給水   │
├───────────────────────────────┤
│ 0    6    12    18    24      │
│ ██①██ ② ③██   ①█████████      │  ← 1日の帯
├───────────────────────────────┤
│ ③ 給水  9:30〜10:00            │  ← 選んでいる場所のカード
│ …                              │
│ [＋ 次の場所] [家に帰った] [送る]│
└───────────────────────────────┘
```

### 2.1 はじめに（初回だけ）
- 中央のダイアログで説明する:
  - 何に使うか（災害時に水や食べ物がもらえる場所を見つける仕組みを考えるため）
  - 回答は LINE で送ってもらう。サーバーには保存しない
  - 公開しない。家の位置は約100mに丸める
- 呼び名（ニックネームでよい、20文字まで）を入れて「はじめる」
- 2.1b の案内のあとに出る

### 2.1b 使い方の案内（開いてすぐ）
- 初めて開くと、まず8段の案内が出る。説明する場所だけを明るく抜き、その近くに説明のカードを出す。「次へ」で次の段へ進む
  1. このページについて（画面の中央）
  2. 書く日を選ぶ（タブと ＋）
  3. 場所を探す（検索）
  4. まず家をタップ（地図）
  5. 次に行った場所をつなぐ（「＋ 次の場所」）
  6. 時刻と、何をしに行ったか（下のカード）
  7. 1日の帯で見直す
  8. 家に帰って、送る（「家に帰った」「送る」）
- 案内が終わると（「とばす」・Esc でも）、2.1 の説明と呼び名のダイアログが出る
- 見終わったことは書きかけと一緒に保存し、2回目からは出さない（送る内容には入らない）。右上の ? からいつでも見直せる

### 2.1c 場所の検索
- 地図の上に検索欄を置く。入力が止まって0.4秒後（2文字以上）か、検索キーで探す
- 店や施設の名前は Photon（OpenStreetMap をもとにした検索。今見ている地図の中心の近くを優先）、住所と町名は国土地理院の地名検索。両方に同時に聞き、Photon 5件 → 国土地理院 5件の順に並べる。どちらも鍵なしで使える
- 候補を選ぶと地図がそこへ動き、真ん中のピンが合う。登録は地図の下のボタンで行う
- 見つからないときは「近くの町名や目印で探すか、地図をタップしてください」、通信できないときは「検索できませんでした」と出す
- 限界: OpenStreetMap に載っていない店や施設は見つからない。検索した言葉は Photon と国土地理院に送られる
- 地図の出典表示に「検索: Photon・国土地理院」を足す

### 2.2 日のタブ
- 最初は「ふだんの日」「地震の後の日」の2つ
- どの日にも日付を入れる。選んでいるタブにはカレンダーの印を付け、もう一度押すと日付のダイアログ（`<input type="date">`、足した日は「この日を消す」も）を出す。日付はタブの名前に出し（例「ふだん 7/20」「地震後 7/30」）、日付がまだの日のタブは赤い枠にする
- 「＋」で日を足す。足した日は消せる（「この日を消す」→ 確認）
- 「給水や炊き出しに行った日を優先して」は、画面には出さず使い方の案内（2.1b）で伝える

### 2.3 つなぐ（真ん中のピン）
画面に指示の文は出さず、部品で操作を示す。
1. 地図の真ん中に、いつもピンを立てておく（ピンの先が地図の中心）。地図を指で動かしてピンを合わせる。地図をタップすると、そこへ地図が動いてピンが合う
2. 地図の下の大きなボタンで登録する。家がまだなら「ここを家にする」、家があれば「ここを次の場所にする」。登録すると前の場所から直線が伸び、新しい場所のカードが開く（2日目以降は家の位置を最初から入れておく）
3. 「家に帰った」を押すと、家の位置に戻る場所が足される
4. 地図上の点はドラッグで動かせる。点をタップするとカードが開く
5. カードを開いている間は、真ん中のピンと登録ボタンを隠す。地図をタップするとカードが閉じ、ピンがそこへ動く
- 種類が自宅の場所は、すべての日で同じ位置にする（1か所を動かすと全部動く）
- 地図の初期位置は八代市の中心（本体の `web/app.js` の START と同じ）

### 2.4 場所のカード
| 項目 | 入れ方 | 必須 |
|---|---|---|
| 時刻 | 「何時ごろ着いた？」を時（0〜23時）と分（00/15/30/45）で選び、「どのくらいいた？」を 15分 / 30分 / 1時間 / 2時間 / 3時間 / それ以上… のボタンで選ぶ。「それ以上…」で「何時ごろ出た？」を直接選べる。1件目（家）は「何時ごろ家を出た？」だけ。2件目以降の家は「何時ごろ帰った？」で、長さに「朝まで」（24時まで）を足す | 必須 |
| 種類 | 自宅 / 職場・学校 / 店 / 給水 / 炊き出し / 避難所 / 車中泊 / 知人の家 / その他 | 必須 |
| 何しに | 自由に1行（50文字まで） | 任意 |
| 知ったきっかけ | お隣さん / インスタ / LINE / 張り紙 / 通りがかり / いつも行く / その他 | 任意 |
| ふだんも行くか | はい / いいえ | 必須 |
| そこまでの移動手段 | 徒歩 / 車 / 自転車 / その他 | 任意（家の①は無し） |

- 時刻の既定値: 前の場所の「出た時刻」を着いた時刻に入れておく
- 着いた時刻を直したときは、選んでいた長さを保って出た時刻を計算し直す
- 出た時刻が着いた時刻より前なら「翌日まで」とみなし、カードに「翌日」と出す（夜をまたぐ車中泊など）
- 「この場所を消す」ボタン

### 2.4b 50代の人でも入力しやすくする
- 文字は本文 18px、項目名 17px（太字・濃い色）。薄い灰色の小さな文字は使わない
- ボタン・タブ・入力欄の高さは 48〜52px。押せる部品の枠は濃いめの線（`--line`）
- 種類・ふだんも行くか・知ったきっかけ・移動手段は、プルダウンでなく大きなボタンを並べる。選んだものは紺で塗って ✓ を付ける。任意の項目は、選んだボタンをもう一度押すと外せる
- カードは「Nか所目」の見出しのあと、必ず書くもの（ここは何ですか？ → 時刻 → ふだんも行く場所ですか？）を上に並べ、任意のもの（何をしに行った？・どうやって知った？・移動手段）は「くわしく（任意）」の下にたたむ
- まだ入れていない必須の項目には、項目名の横に「未入力」と赤で出す

### 2.4c 入力欄は場所を決めたときだけ出す
- 場所を置いた・点や帯をタップしたときだけ、下に場所のカードを出す。「決定して地図に戻る」か「閉じる」でカードを閉じ、地図を広く見せる
- カードを閉じている間は、1日の帯と下のボタン（家に帰った・送る）だけを出す。カードを開いたときも、下の欄は画面の高さの半分まで
- 入力するところ（選ぶボタン・入力欄）は、うすい紺の地（`--input`）にして、説明の文字と区別する
- 未入力の必須項目は、項目全体を赤い地にし、左に赤い線、項目名を赤にする。地図の点も、未入力がある場所は赤い枠にする

### 2.5 1日の帯
- 0時から24時の横の帯に、その日の滞在を並べる。色は種類ごとではなく、選んでいる場所だけアクセント色、他は無彩色（`unslop` の方針と揃える）
- 滞在が入っていない時間はうすい斜線で見せ、抜けに気づけるようにする
- 帯の滞在をタップするとその場所のカードが開く
- 時刻の重なり（前の場所を出る前に次に着いている）はカードに「時刻が前の場所と重なっています」と出す。送るのは止めない

### 2.6 送る
- 「送る」→ 確認のダイアログに、日ごとの件数と、時刻が抜けている場所の数を出す
- 「コピーして LINE で送る」: 回答の JSON を `navigator.clipboard.writeText` でコピーし、「コピーしました。LINE に貼り付けて送ってください」と出す
- コピーできない端末のために、同じ JSON を選択しやすい欄（`<textarea readonly>`）にも出す
- 「この端末から消す」: 書きかけの保存を消す（確認あり）

## 3. 回答のデータ

```json
{"v":1,"name":"A","home":[32.507,130.602],
 "days":[
  {"label":"ふだんの日","date":"2026-07-20","stays":[
    {"lat":32.507,"lon":130.602,"from":"00:00","to":"07:45","type":"home","usual":true},
    {"lat":32.51234,"lon":130.60111,"from":"08:00","to":"08:30","type":"shop",
     "purpose":"朝ごはん","heard":"usual","usual":true,"mode":"car"}]},
  {"label":"地震の後の日","date":"2026-07-30","stays":[]}]}
```

| キー | 値 |
|---|---|
| v | 形式の版。今は 1 |
| name | 呼び名 |
| home | 家の位置 [緯度, 経度]、小数3桁 |
| days[].label / date | 「ふだんの日」か「地震の後の日」/ `YYYY-MM-DD`（未入力なら null） |
| stays[].lat, lon | 小数5桁（約1m）。種類が home のときは home と同じ値 |
| stays[].from, to | `HH:MM`。to < from は翌日まで |
| stays[].type | home / work / shop / water / food / shelter / car_sleeping / friend / other |
| stays[].purpose | 文字列か省略 |
| stays[].heard | neighbor / instagram / line / poster / passing / usual / other か省略 |
| stays[].usual | true / false |
| stays[].mode | walk / car / bicycle / other か省略 |

- 種類のキーは、本体の `app/rules.py` の Kind（water / food / shelter / car_sleeping / other）と重なるものは同じ名前にする
- JSON は空白なしで出す（LINE に貼る文字数を減らすため）

## 4. 書きかけの保存

- 入力のたびに回答の JSON を `localStorage` に保存し、開き直すと復元する
- `localStorage` が使えない（プライベートモードなど）ときは保存せずに動く（try/catch）
- 送ったあとも自動では消さない（送り直せるように）。「この端末から消す」で消す

## 5. プライバシーと扱い

- サーバーには何も送らない。地図のタイル（OpenFreeMap）を読むときに、表示している範囲がタイルの配信元に伝わるのは本体と同じ
- 家の位置は丸めてから保存・出力する。丸める前の値はどこにも残さない
- 受け取った回答（JSON）はリポジトリに入れない。段階2以降で使い、公開するのは水増しした後のデータだけ
- 回答してくれた人から「やめたい」と言われたら、受け取った回答と、それから作ったデータを消す

## 6. 先に伝える限界

- 思い出して書くので、時刻と場所はタイムラインの記録より粗い
- 道順は入らない。場所と場所の間は段階3で補う
- LINE の1通に入る文字数には上限がある。長めの回答（3日 × 各10か所）で実際に送れるか確かめ、入らなければ「ファイルで保存」ボタン（JSON のダウンロード）を足す

## 7. 確認のしかた

- ヘッドレスの Chromium（`scripts/ui-check.js` と同じ道具）で次の流れを確かめるスクリプトを `scripts/survey-check.js` に置く:
  1. 初回の説明が出て、呼び名を入れて閉じられる
  2. 地図をタップして家を置き、2か所つなぎ、「家に帰った」で閉じる
  3. 時刻と種類を入れると、1日の帯に滞在が出る
  4. 日を足して日付を入れると、タブに日付が出る
  5. 送る → コピーした JSON が §3 の形で、家が小数3桁に丸まっている
  6. ページを開き直すと書きかけが復元される。「この端末から消す」で消える
  7. Console にエラーが出ない
- 390×844（スマホの幅）とダークモードのスクリーンショットを目で見て、崩れていないことを確かめる
