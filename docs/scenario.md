# 紹介動画のシナリオ

> 3本に分ける。1本目 テーマ紹介（約1分30秒）、2本目 デモ（約1分）、3本目 精度紹介（約40秒〜1分）。どれも 16:9。
> 字幕と BGM で作り、声はあとで入れられるようにする。デモの画面（`/?demo=1` の再生）は2本目が中心。組み立ては HyperFrames。

## 1. 目的と使い道

| 本 | 中身 | 長さ | シーン |
|---|---|---|---|
| 1本目 テーマ紹介 | 被災の経験 → 給水や配給の情報がどこから来るかわからない → 公式の情報は 8 つのサイトに分散し、非公式の炊き出しは載らない → 早いのは SNS とお隣さんだが、つながりがないと届かず格差が生まれる → GPS で人の集まりを見つける → 誰も書かなくても1つの地図にまとまり、SNS をしていない人にも届く | 約1分30秒 | A01〜A10 |
| 2本目 デモ | 合成データの画面で、「？」が立ち、近くの人に聞き、地図に載るまで | 約1分（58秒） | B01〜B05 |
| 3本目 精度紹介 | 数え方と、実際の人流データで測った検知の精度 | 約40秒（配慮と今後を入れると約1分） | C01〜C04（C05・C06 は未定） |

- 伝えたいことは1つ: **誰も投稿しなくても、人の動きから、公式に載らない支援拠点が見つかる**
- 3本は、話の流れに合わせて1本ずつ流せる
- 3本を3分以内の1本にまとめた形も作る（つなぎに区切りの札「デモ」「頑張ったこと」を入れ、最後は QR の締め）

## 2. 共通のルール

### 言っていいこと

- 原体験は CLAUDE.md §1 のとおりに書く。足さない、言い換えで強めない
- 数字は §7 の表にあるものだけ。画面に出すときは、出典を画面の下に小さく出す
- デモの画面は合成データであること。A07 と 2本目（B01 の注記と、スマホの下に出し続ける札）で必ず断る
- 検知は候補を出すまで。正体は近くの人に聞いて確かめる

### 書き方の調子

- 感傷的にしない。経験も事実として短く書く（気持ちを表す言葉や、長い間を入れない）
- 文末は常体で、短く切る

### 言わない・描かないこと

- 「八代で震度7」（震度7は宇城市と氷川町）
- 出典のない数字。デモの画面に出る人数（「18 人の集まり」など）を、実際の数字として読ませること
- 合成データでの検知の結果（31/31 など）を、実データの成果として見せること
- 「災害時の実データで 97〜98%」（97〜98% は実際の人流データの1日に集まりを埋め込んだ測定。災害時の実データでの精度は未測定）
- 「個人の軌跡は送らない」を今の機能として言うこと（今の試作は位置をサーバーに送る。端末内での判定は今後の形として言う）
- 「勝手に登録される」（自動で出るのは「？」の候補。確定は近くの人の回答で行う）
- 「格差がなくなる」（地図を見るにはアプリが要るので、言うのは「減らす」まで）
- 「公式の情報は○時間遅い」のような、測っていない遅さ（A05 は発案者の体験として「早かった」と言うまで）
- 報道写真、SNS の画像。実在するサービスの画面の再現（吹き出しはアプリの色で作る）
- 特定の機種に似せたスマホの枠

## 3. 見た目と音

### 見た目

- 背景は紺の無地。色はアプリの3色に絞る
  - 紺 `#1e3a5f`: 非公式・確認済み、見出し
  - オレンジ `#ea8a00`: 未確認の「？」、注目させたいところ
  - 緑 `#0f7b4f`: 公式
  - 赤 `#b91c1c`: 「できない」「届かない」を示す ✕ の印だけ（アプリのエラーの色）
- 文字の太さは 400 と 600 だけ（アプリと同じ）
- アイコンは lucide の線のアイコン（アプリと同じ形）。種類は漢字1文字の札（水・食・物・宿・避）
- デモの画面は、角丸の枠に入れて置く
  - 16:9: 枠を左に置き、テロップを右に出す
  - 9:16: 画面いっぱいに置く
- 時刻は動画の側で大きく重ねる（デモの画面は再生バーを隠して撮るので、アプリの時計は映らない）

### テロップ

- 1つの画面に、1つのメッセージ
- 1秒あたり4文字を目安に、シーンの長さに収める。長い文は2回に分けて出す
- 声を入れるときは、テロップの文をそのまま読む（声は字幕を目で読むより速いので、シーンの長さに収まる）

### 音

- BGM は1本ごとに1曲。どの本も控えめにし、盛り上げない
  - 1本目: 静かで一定の拍。A07（提案）から少し厚くする
  - 2本目: 前に進む拍
  - 3本目: 落ち着いた拍
- 効果音は「？」が立つ瞬間と、ピンが紺に変わる瞬間だけ。小さく短い音にする
- 曲と効果音は、ライセンスを記録できるものだけを使う（出典と条件を残す）

### 作るときの進め方

1. 各シーンの最後の1コマを静止画で並べ、テロップと配置を確かめてから動きを付ける
2. 動きは、見る人が理解すべきことを1つずつ見せきる。次の要素は、前の要素を読み終えてから出す
3. 書き出したら、数字と出典を §7 と突き合わせる

### 1本目の絵の組み立て

1本目は、ばらばらだった情報が1枚の地図にまとまるまでを、絵の流れで見せる。

- 前半（A02〜A06）: 公式の情報は散らばり（A03）、非公式は公式に載らず（A04）、早く届くのは SNS とお隣さん（A05）。それではつながりのない人に届かない（A06）
- 後半（A07〜A10）: 人の点が集まって地図にピンが立ち、最後は公式と非公式のピンが1枚の地図に並ぶ
- 課題とよいところを1対1で対応させる。課題①「一元化されていない」（A03〜A04）には A08「誰も書かなくても、1つの地図にまとまる」、課題②「つながりがないと届かない」（A06）には A09「SNS をしていない人にも届く」で答える

シーンはただ切り替えない。前のシーンの絵の一部が、次のシーンの絵になるようにつなぐ。

| つなぎ | 引き継ぐもの |
|---|---|
| A01 → A02 | 市役所の印へ寄りながら地図が明るくなり、そのまま町の地図になる |
| A02 → A03 | 町の地図から引きながら、地図が紺の地に沈む |
| A03 → A04 | 8つの窓が左半分に重なって、1枚の「公式」のリストになる |
| A04 → A05 | 右の店が左へ縮み、A05 の道の起点（丸い札）になる |
| A05 → A06 | 道が消え、受け取る人が左へ動いて「SNS をしている人」になる。右から「SNS をしていない人」が入る（A09 と同じ2人） |
| A06 → A07 | 2つの原因と「情報格差」が薄くなり、中央から地図が丸く広がる |
| A07 → A08 | 「？」のピンに寄り、ピンの白い丸が画面いっぱいに広がって紙色の地になる |
| A08 → A09 | 店とピンが縮んで、中央の小さな地図の札になる |
| A09 → A10 | 中央の地図の札が広がって、画面いっぱいの夜の地図になる |

画面の決まりごと（1920×1080 で書く。秒はシーンの頭から数える）:

- テロップは、左 120px・下 120px から左寄せで、56px・太さ 600 にする
  - 紙色や地図の上に出すときは、白い角丸の帯に紺の文字にする
  - 紺の地に出すときは、帯なしの白い文字にする
- 2行目のテロップは、1行目の下に足す（1行目を消さない）
- テロップは左から拭うように出し（0.55 秒）、少し遅れて大事な語にオレンジのマーカーを引く。マーカーを引く語は各シーンのテロップの〈〉の中
- 出典と地図の出典は、右下に出す（テロップと重ならないように）。読ませる文字は 28px 以上にする
- 主役の絵（店、人、給水車、配給、スマホ、家、市役所、テレビ）は、塗りのピクトグラムで描く（紺の塗り、店の日よけはオレンジと白の縞、公式は緑）。札の中の小さな印だけ lucide の線のアイコンを使う
- 動きは緩急を付ける。主役の出現は弾ませ（ピンは落ちて弾む、✕ は回って震える、数字は大きく）、背景はゆっくり流す。届いた・立ったの瞬間は輪を1回広げる
- 「できない」「届かない」を矢印や線で見せるときは、止まった先に赤い ✕ の印（直径 64px の赤い丸に白い ✕）を付ける（A04、A06）。A05 の下の道には付けない（遅いだけで、届かないわけではない）。A02 の点線にも付けない（市役所やテレビから情報が来ないわけではなく、どこから来るかが決まっていないだけなので）
