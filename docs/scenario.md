# 紹介動画のシナリオ

> 本編 16:9・約3分20秒。字幕と BGM で作り、声はあとで入れられるようにする。
> 中にアプリのデモ画面（`/?demo=1` の再生）を入れる。組み立ては HyperFrames。

## 1. 目的と使い道

1本の本編から、2本を切り出す。

| 版 | 向き・長さ | 使うシーン | 見る人 |
|---|---|---|---|
| 本編 | 16:9（1920×1080）・約3分20秒 | S01〜S23 | 審査員（提出用。発表を聞いていなくても伝わるように作る） |
| 発表用 | 16:9・約40秒 | S15〜S18 | 発表の会場（背景はスライドで話すので、デモだけ流す） |
| SNS 用 | 9:16（1080×1920）・約60秒 | S01・S05・S10・S15・S16・S18・S23 | SNS で流れてきた人 |

- 伝えたいことは1つ: **誰も投稿しなくても、人の動きから、公式に載らない支援拠点が見つかる**
- SNS 用は、同じテロップのままレイアウトだけ縦に組み直す。アプリの画面はスマホの縦長なので、縦の画面にそのまま収まる

## 2. 共通のルール

### 言っていいこと

- 原体験は CLAUDE.md §1 のとおりに書く。足さない、言い換えで強めない
- 数字は §7 の表にあるものだけ。画面に出すときは、出典を画面の下に小さく出す
- デモの画面は合成データの再生であること。S14 で必ず断る
- 検知は候補を出すまで。正体は近くの人に聞いて確かめる

### 言わない・描かないこと

- 「八代で震度7」（震度7は宇城市と氷川町）
- 出典のない数字。デモの画面に出る人数（「18 人の集まり」など）を、実際の数字として読ませること
- 合成データでの検知の結果（31/31 など）を、実データの成果として見せること
- 「災害時の実データで 97〜98%」（97〜98% は実際の人流データの1日に集まりを埋め込んだ測定。災害時の実データでの精度は未測定）
- 「個人の軌跡は送らない」を今の機能として言うこと（今の試作は位置をサーバーに送る。端末内での判定は S22 で今後の形として言う）
- 報道写真、SNS の画像。実在するサービスの画面の再現（吹き出しはアプリの色で作る）
- 特定の機種に似せたスマホの枠

## 3. 見た目と音

### 見た目

- 背景は紺の無地（スライドと同じ）。色はアプリの3色に絞る
  - 紺 `#1e3a5f`: 非公式・確認済み、見出し
  - オレンジ `#ea8a00`: 未確認の「？」、注目させたいところ
  - 緑 `#0f7b4f`: 公式
- 文字の太さは 400 と 600 だけ（アプリと同じ）
- アイコンは lucide の線のアイコン（アプリと同じ形）。種類は漢字1文字の札（水・食・物・宿・避）
- デモの画面は、角丸の枠に入れて置く
  - 16:9: 枠を左に置き、テロップを右に出す
  - 9:16: 画面いっぱいに置く
- 時刻は動画の側で大きく重ねる（デモの画面は再生バーを隠して撮るので、アプリの時計は映らない）

### テロップ

- 1つの画面に、1つのメッセージ
- 1秒あたり4文字を目安に、シーンの長さに収める。長い文は2回に分けて出す
- 文末は常体で、短く切る。声を入れるときは、テロップの文をそのまま読む（声は字幕を目で読むより速いので、シーンの長さに収まる）

### 音

- BGM は1曲を通して流し、章ごとに音量と厚みを変える
  - 原体験（S03〜S06）: ピアノなど静かな音だけ
  - 背景の数字と課題（S07〜S09）: 低い音を少し足す
  - 提案からデモ（S10〜S18）: 拍が入り、前に進む感じ
  - 検証から締め（S19〜S23）: 落ち着いて終わる
- 効果音は「？」が立つ瞬間と、ピンが紺に変わる瞬間だけ。小さく短い音にする
- 曲と効果音は、ライセンスを記録できるものだけを使う（出典と条件を残す）

### 作るときの進め方

1. 各シーンの最後の1コマを静止画で並べ、テロップと配置を確かめてから動きを付ける
2. 動きは、見る人が理解すべきことを1つずつ見せきる。次の要素は、前の要素を読み終えてから出す
3. 書き出したら、数字と出典を §7 と突き合わせる

## 6. デモの撮影リスト

サーバーを `DEMO=1 docker compose up -d` で起動し、http://localhost:18080 で撮る。どれも最初に「同意して始める」を押してから再生する（キーはスペース）。

| 撮影 | 使うシーン | URL | 時刻 | 操作 |
|---|---|---|---|---|
| D1 | S01 | `/?demo=1&from=11:30&speed=5&paused=1&at=32.512,130.616` | 11:30 → 12:00 | 再生だけ。12:00 に八代市働く婦人の家の前に「？」が立つ。中心を集まりから 500m 以上離しているので、質問のカードは出ない |
| D2 | S14〜S17 | `/?demo=1&from=08:00&speed=5&paused=1&at=32.49937,130.59743` | 8:00 → 9:00 | 8:50 に古城町団地の前に「？」が立ち、質問のカードが出る → 「給水」を押す → 紺の「水」になる。同じ 8:50 に立つ緑のピン（八代コミュニティセンター）を押して、詳細を出す |
| D3 | S18・S23 | `/?demo=1&from=08:00&speed=15&paused=1` | 11:00 → 21:00 | `at` を付けず、台本の範囲の全体を映す。再生だけ |

- 時刻と場所は `web/demo/timeline.json` に合わせてある（検知の時刻: 古城町団地 530分 = 8:50、八代コミュニティセンター 530分、八代市働く婦人の家 720分 = 12:00、球磨川河川緑地 1240分 = 20:40）。データを作り直したら確かめ直す
- 画面の大きさ: スマホの幅（390×844、画素の密度 3 倍 = 1170×2532）。9:16 の画面いっぱいに置いても粗くならない
- この機械（GPU なし）の画面録画では、点の動きがカクつく。時刻を渡してその瞬間の画面を描かせ、1コマずつ撮る仕組みが要る（アプリに時刻を指定する数行を足す。未着手）
- D3 は 10時間を10秒に縮める。1コマずつ撮るなら、撮るときに時刻の進め方を決める
